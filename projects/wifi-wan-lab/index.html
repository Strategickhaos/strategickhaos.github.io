The network question
Wi-Fi → client adapter → Ethernet → OPNsense

The router isn't fooled: the adapter provides a real Ethernet link while moving the upstream packets over Wi-Fi. Typically this is routing / NAT, not transparent Layer-2 bridging.

Routed client / WISP · Most compatible path. Expect NAT between the upstream Wi-Fi and your OPNsense network.

What it actually achieves

OPNsense receives Ethernet WAN connectivity sourced from Wi-Fi. Devices can reach upstream internet without requiring OPNsense itself to drive a Wi-Fi radio.

Engineering limitation

Often creates double NAT; upstream and local LAN must not overlap. It does not grant ownership of or bypass restrictions on the upstream network.

02 / BUILD WITHOUT BREAKING THE LAN

Installation runbook

Conservative steps for a lab using networks and equipment you control or are authorized to use.

WISP → OPNsense WAN

  1. Keep the current internet connection intact.
  2. Join the authorized Wi-Fi network with a WISP/client router.
  3. Connect its Ethernet LAN port to the OPNsense WAN port.
  4. Set OPNsense WAN to DHCP; use a different subnet on LAN.
  5. Verify WAN IP, DNS, HTTPS, and reconnect behavior.

04 / SOURCE NOTES

What's supported—and what's not

Reliable foundation

OpenWrt supports a routed Wi-Fi station/client network with a separate LAN and NAT. OPNsense supports wired WAN/LAN interfaces and can obtain its WAN address via DHCP. These let an upstream Wi-Fi link be delivered over Ethernet.

Do not conflate the devices

An Arcadyan G5AR is a carrier-managed 5G gateway, not an arbitrary wireless client bridge. T-Mobile currently documents automatic Home Internet Backup connection with G4AR; other gateways can use manual activation via T-Life.
